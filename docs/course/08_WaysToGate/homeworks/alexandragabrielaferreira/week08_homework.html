Problem 1

“Using flowGate, go ahead and create your own series of gates for either our data or your own for any cell populations that might interest you. Once done, save the GatingSet, and then successfully reload it. Add another gate, but intentionally misdraw it. Then proceed to visualize, identify and correct it, before saving again.”

Solution step by step

  1. activate the libraries
  2. get directory
  3. read full path for fcs files
  4. load fcs files into a cytoset
  5. create a gating set from the cytoset
  6. get the fluorophores into a variable (colnames followed by str_detect to exclude scatters and time)
  7. apply a transformation:
  1. attribute the transformation function to an object
  2. use transformerList() to apply the transformation from the step prior to the fluorophores only from step 6.
  3. apply transform() to pass the list of transformations created in the step prior.
  1. use gs_gate_interactive(gs = gatingsetobject, filterID= “name of the gate”, sample = 1, dims = list(“parameter 1”, “parameter 2”), subset=“parent gate”) to draw 1 gate

OR

  1. use a tibble to provide a sequential gating strategy
  • is it possible to create this outside of R environment, using a notepad or spreadsheet software?
  1. save gating set
  2. reload gating set
  3. draw the wrong gate
  4. visualize it using autoplot for one of the samples (as realistically there’s when I’d notice it)
  5. redraw hint use argument regate = TRUE in the gs_gate_interactive()
  6. check the new gate was applied properly
  7. save correct gating set.

Let’s design a sequential gating strategy. For a set like this, this would be my strategy: cells > singlets > live (FSC-A, Viability) > Lin neg CD45pos (CD45, Dump) > Tcells (CD3, SSC-A) > CD4pos vs CD8pos vs DN (CD4, CD8) in CD4pos > Tregs (CD25pos FoxP3pos) vs FoxP3neg

Final thoughts:

I think autogating is great for those black and white populationsm, where there is clear definition for neg and pos populations.

And even then, when I tried using flowClust in a CD4 vs CD8 it couldn’t do it properly and resulted in a terrible merge of both populations. I’m thinking that’s most likely due to the fact flowClust is not suitable for this kind of separation and just overides whatever was drawn first or adds to the 1st gate it created.

openCyto has more gating methods that would probably be more suitable for this endeavour. Maybe a quadGate.tmix would work (I’ll explore this later.)
